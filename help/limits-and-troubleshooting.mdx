Scouty applies internal limits to provider search, AI generation, and email activity. These controls protect account and application capacity. The exact allowance can depend on the active production configuration, so the documentation does not treat a code default as a purchased entitlement.

## Search limits

Search actions include match previews, company pages, decision makers, and work email reveal. Valid cached or snapshotted results can avoid a new provider request.

If Scouty reports that today's search limit was reached, new provider-backed searches pause until the reset. The search day resets at **00:00 UTC**.

To convert the reset:

1. Find your current UTC offset.
2. Add the offset to 00:00 UTC.
3. Account for daylight-saving changes in regions that use them.

Examples: Vietnam resets at 07:00 local time (UTC+7). A UTC-4 location resets at 20:00 on the previous local calendar day.

## Cache and snapshot behavior

Scouty caches eligible research to reduce repeated provider and AI work. It also saves each company-lead page automatically for its campaign version.

- Reloading a saved page does not intentionally repeat the provider search.
- An empty page is saved so **Show more companies** does not repeatedly request it.
- Duplicate company domains across pages are collapsed while preserving first-seen order.
- A changed campaign version receives a separate snapshot.
- Scouty shows the source timestamp or stale-data note when an older valid cache is used.
- If the database cannot confirm a snapshot, Scouty returns an error rather than treating the failure as a cache miss and charging for a new search.

## Common problems

### “You've reached today's search limit”

Wait until 00:00 UTC, then retry. Continue reviewing results that are already saved. Repeatedly pressing **Check matches** does not bypass the allowance.

### Company research fails

Check the website spelling and make sure the public site is reachable. Retry the step. Use the business form when no public website exists. A failed analysis does not consume the anonymous profile trial.

### Market must be selected

Open **Not quite right? Edit the details**, select a specific market or **Global**, and save. Scouty requires this context before competitor research.

### A step disappeared after editing

Changing the company profile, campaign, or targeting invalidates dependent later results. Continue forward from the changed step. Sent email and saved project history are not rewritten.

### Work email cannot be revealed or verified

Choose another decision maker. Scouty will not send to an unverified address.

### Send is still being confirmed

Select **Check now**. Do not create another draft for the same send. Scouty reconciles the mailbox because retrying an uncertain send could create a duplicate.

### Replies are not current

Open the project and select **Check for replies**. If synchronization returns an error, wait and retry without sending another opening email.

### Calendar connection failed or was canceled

Retry **Connect Google Calendar** from the project. Use **Set up later** when you need to continue without Calendar. See [Google Calendar and meetings](/meetings/google-calendar#recover-from-connection-problems).

### Custom domain remains pending

Compare every DNS name, value, type, proxy setting, and priority with the table. Wait for propagation, then select **Check connection**. See [Custom domain](/settings/custom-domain#wait-for-dns-propagation).

## Restore your progress

Reload the current URL first. Scouty restores valid server data and the browser snapshot. Use the stepper to review an already reached step and **Next step: N** to move forward without rerunning it.

If you changed account, company, campaign, or input while a request was running, Scouty ignores a late response that belongs to the old context. Run the action again in the current context.

## Information to collect for support

Use the support channel provided with your Scouty account. Include:

- the page and project name;
- the action and button you used;
- the approximate time and your time zone;
- the visible error text and status;
- whether retrying or reloading changed the result;
- a screenshot with personal data and credentials removed.

Never share passwords, API keys, Firebase tokens, DNS account credentials, or private authentication links.
